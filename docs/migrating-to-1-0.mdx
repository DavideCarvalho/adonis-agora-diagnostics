1.0 keeps the 0.x API as it is. Every export, config key and channel name works the same way, so most apps only need to bump the package and check their Node version. 1.0 also adds [listeners](/docs/diagnostics/listeners), described at the end of this page.

## Use Node.js 24 or newer

`@adonis-agora/diagnostics` 1.0 requires Node.js 24 or newer and is tested on Node.js 24 and 26. Update the Node version your app runs on, in your `package.json`, `.nvmrc`, Dockerfile and CI.

Before:

```json title="package.json"
{
  "engines": { "node": ">=20.6.0" },
  "dependencies": {
    "@adonis-agora/diagnostics": "^0.3.0"
  }
}
```

After:

```json title="package.json"
{
  "engines": { "node": ">=24" },
  "dependencies": {
    "@adonis-agora/diagnostics": "^1.0.0"
  }
}
```

```dockerfile title="Dockerfile"
FROM node:24-alpine
```

## `@adonisjs/queue` 0.7 is supported

If you relay diagnostics through the [queue transport](/docs/diagnostics/transports), you can upgrade `@adonisjs/queue` to 0.7. Version 0.6 still works. Your `config/diagnostics.ts` stays the same:

```ts title="config/diagnostics.ts"
import { defineConfig, transports } from '@adonis-agora/diagnostics'

export default defineConfig({
  default: 'queue',
  transports: {
    queue: transports.queue(),
  },
})
```

## Listeners run through the transport

1.0 adds listener classes. Work you did inside an `onDiagnostic` function, which runs inline and is lost when it throws, can move to a listener and get retries from the transport you select.

Before:

```ts title="start/diagnostics.ts"
import { onDiagnostic } from '@adonis-agora/diagnostics'
import AgentRunStats from '#services/agent_run_stats'

onDiagnostic('agent', 'run.finished', async (event) => {
  await new AgentRunStats().record(event.payload)
})
```

After:

```ts title="app/listeners/diagnostics/track_agent_run.ts"
import { inject } from '@adonisjs/core'
import { OnDiagnostic, type DiagnosticEventOf } from '@adonis-agora/diagnostics'
import AgentRunStats from '#services/agent_run_stats'

@inject()
export default class TrackAgentRun {
  constructor(protected stats: AgentRunStats) {}

  @OnDiagnostic('agent', 'run.finished')
  async handle(event: DiagnosticEventOf<'agent', 'run.finished'>) {
    await this.stats.record(event.payload)
  }
}
```

```ts title="config/diagnostics.ts"
import { defineConfig, transports } from '@adonis-agora/diagnostics'

export default defineConfig({
  default: 'queue',
  transports: {
    queue: transports.queue({ queue: 'diagnostics', retries: 5 }),
  },
})
```

`onDiagnostic` with a function keeps working unchanged, as an in-process observer.

### `app/listeners/diagnostics` is read at boot

Every module in `app/listeners/diagnostics` is imported at boot to find listener classes. If your app already uses that directory for something else, point discovery elsewhere, or turn it off:

```ts title="config/diagnostics.ts"
import { defineConfig } from '@adonis-agora/diagnostics'

export default defineConfig({
  listenersPath: false,
})
```

### The queue transport also runs listeners

With `default: 'queue'`, listeners run in the queue worker as `agora.diagnostics.listener` jobs. Workers already started with `node ace queue:work --queue=<your diagnostics queue>` pick them up with no change.

### Custom transports

A custom `TransportProvider` that returns a teardown function keeps working: listeners then run in the processes your transport relays events to. To run listeners yourself, return a handle with `deliver`; see [A transport that runs listeners](/docs/diagnostics/transports#a-transport-that-runs-listeners).

### Events carry an `id`

Every event from `emit` and `trace` now has an `id`, unique per event and the same in every process the event reaches. Code that reads events keeps working; use `event.id` to make a listener idempotent.

<Callout type="info" title="Mixed versions in one app">
Libraries that still depend on 0.x and your app on 1.0 can run side by side. Events emitted by either version reach the same `onDiagnostic` handlers, and the Redis and queue transports relay them between processes on different versions.
</Callout>
