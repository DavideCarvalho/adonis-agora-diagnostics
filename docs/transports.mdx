`node:diagnostics_channel` is **process-local**: an event emitted in your web process is invisible to a worker, and vice versa. A **transport** relays selected `agora:<lib>:<event>` channels across processes so `onDiagnostic` handlers (and any `getChannel(...).subscribe(...)`) fire everywhere.

The transport also decides how [listeners](/docs/diagnostics/listeners) run: in every process with `redis`, once in a worker with retries with `queue`, or as a durable run with `durable`.

Transports ship **inside `@adonis-agora/diagnostics`** and are selected in `config/diagnostics.ts` — there are no separate `@adonis-agora/diagnostics-redis` / `-queue` packages. You pick a `default` transport and list the ones you use under `transports`, exactly the way `@adonisjs/session` picks a `store` or `@adonisjs/cache` picks a store driver. The driver's peer dependency (`@adonisjs/redis`, `@adonisjs/queue`, `@adonis-agora/durable`) is imported lazily, only when you actually select it.

## Configuring a transport

<Steps>
<Step>

Pick a `default` and declare your transports with the `transports` factory:

```ts title="config/diagnostics.ts"
import { defineConfig, transports } from '@adonis-agora/diagnostics'

export default defineConfig({
  otel: true,

  // The transport whose relay starts in this process.
  default: 'redis',

  // Which local channels to fan out across processes.
  forward: { libs: ['resilience', 'durable'] }, // or { all: true }

  transports: {
    // Authenticated with the app's APP_KEY, nothing to add. See "Authenticating the relays".
    redis: transports.redis({ connection: 'main' }),   // @adonisjs/redis + ioredis
    queue: transports.queue({ queue: 'diagnostics' }), // @adonisjs/queue
    durable: transports.durable({ retries: 5 }),        // @adonis-agora/durable
  },
})
```

</Step>

## Config reference

The published config file takes seven keys, all optional. `defineConfig` is an identity helper — it exists to type-check the object you pass it.

| Key | Type | Default | What it does |
| --- | --- | --- | --- |
| `otel` | `boolean` | `true` | Bridge `trace()` spans to OpenTelemetry when an OTel SDK is resolvable. `false` keeps the `emit`/`trace` path OTel-free even with an SDK installed. See [OpenTelemetry](/docs/diagnostics/opentelemetry). |
| `default` | `string` | — | Name of the transport (a key of `transports`) whose relay starts in **this** process. Omit for local-only diagnostics. A name missing from `transports` throws at boot. |
| `role` | `'all' \| 'api' \| 'worker'` | `'all'` | Which half of a split deployment **this** process is. `'api'` emits and hands work to the transport but never consumes or runs listeners; `'worker'` consumes and runs them. `'api'` and `'worker'` need a `default` transport, or boot fails. See [Split deployments](#split-deployments). |
| `forward` | `ChannelSelection` | `{}` | Which local channels the relay forwards: `{ libs }`, `{ channels }`, `{ all }`. See [What gets forwarded](#what-gets-forwarded). |
| `nodeId` | `string` | random per process | Identifies **this** process on the wire. A relayed event carries the id of the process that forwarded it, and a process drops events stamped with its own id — that's what stops an event from bouncing back to its origin. Set it only when you need a stable, human-readable id (e.g. in logs); the random default is correct for every normal deployment. |
| `listenersPath` | `string \| false` | `'app/listeners/diagnostics'` | Directory whose listener classes are registered at boot. See [Listeners](/docs/diagnostics/listeners). |
| `transports` | `Record<string, TransportProvider>` | `{}` | The named transports you can select with `default`. Values come from the `transports` factory, or from [your own transport](#write-your-own-transport). |

Declaring a transport costs nothing: the factories return a lazy thunk, and the driver's peer dependency is imported only when that transport is the selected `default`. So it is fine to list Redis, queue *and* durable and pick between them per environment: a transport that is listed but not selected never loads its driver and never throws, even when the driver isn't installed.

### What gets forwarded

`forward` is a single `ChannelSelection`, shared by whichever transport starts:

| Field | Meaning |
| --- | --- |
| `libs` | Forward **every** event of these libs — including channels registered later (e.g. `['resilience', 'durable']`). |
| `channels` | Forward these exact `{ lib, event }` pairs, in addition to `libs`. |
| `all` | Forward **every** `agora:` channel. Overrides `libs`/`channels`. |

Both transports share the same selection engine (`createChannelSelector`) and the same loop-guard design — they differ only in how a selected event leaves the process.

### Forwarding cost on the emitter

Neither built-in transport does I/O inside `emit()`. A selected event is pushed onto an in-memory queue, and the queue is drained once per event loop turn (`setImmediate`), in emit order across all channels. That drain is where events are serialized and sent, as one batch per turn: one Redis pipeline, or one `dispatchMany` call to the queue. Each event is still its own message or job on the wire.

Two consequences:

- The payload is serialized when the turn ends, not when `emit()` is called. A payload object the emitter mutates synchronously after `emit()` goes out with its state at flush time, which is also the state in-process subscribers holding the same reference see.
- Stopping the relay sends whatever is still queued, synchronously, before it unsubscribes. Graceful shutdown doesn't lose the last turn's events.

## The Redis transport

`transports.redis(config)` relays over [`@adonisjs/redis`](https://docs.adonisjs.com/guides/digging-deeper/redis) pub/sub. A forwarded event is published to a Redis channel; every other process subscribed to that channel checks the message is authentic and re-emits it onto its local bus. Echoes are suppressed by `nodeId`, and a re-emit guard stops a re-emitted event from being forwarded back — so events never loop. The events of one turn go out as a single ioredis pipeline, one message per event. A payload that can't be serialized (a circular reference) drops only that event.

```ts
transports.redis({
  connection: 'main',                 // @adonisjs/redis connection name (default: the default one)
  redisChannel: 'agora:diagnostics:relay', // Redis channel to relay on (this is the default)
  // nothing to add: the app's APP_KEY authenticates it (across apps: secret or crypto)
  maxRemoteChannels: 256,             // new channels other processes may create here (default 256)
})
```

Redis is a broadcast: [listeners](/docs/diagnostics/listeners) run in every process that receives the event, the emitting one included. The libs your listeners listen to are relayed on top of `forward`, so you don't have to list them twice. A listener that throws is logged and the event is dropped for it.

A Redis client that is subscribed cannot also publish, so the transport needs two legs. The **publisher** is the raw ioredis client behind the named `@adonisjs/redis` connection — owned by `@adonisjs/redis`, and never closed here. The **subscriber** is a `duplicate()` of it, created and owned by the transport itself; `@adonisjs/redis` does not track it, so the transport closes it on teardown. Without that close, the open socket would keep the process alive and a graceful shutdown (or a test run) would hang.

### Authenticating the relays

Neither Redis nor a queue backend is a trust boundary. Whoever can publish on the relay channel, or write a job into the queue (another app on a shared Redis, a leaked password, an SSRF), could otherwise put events on every process's bus (fake events that Telescope, the dev tools, metrics and your listeners take as real, on channel names of their choosing) or, with the queue transport, run any of your listeners with input of their choosing. So every Redis message and every queue job is authenticated, and **a Redis or queue transport that cannot authenticate refuses to start**. Every process on the same `redisChannel` (or queue) uses the same mode.

#### Same app: nothing to configure

The relays carry events between the processes of **one app** (web, queue workers, schedulers), and those share the app's `APP_KEY`. So with nothing configured, both transports authenticate with a key derived from it, and `config/diagnostics.ts` has no auth line:

```ts title="config/diagnostics.ts"
transports: {
  redis: transports.redis({ connection: 'main' }),
  queue: transports.queue({ queue: 'diagnostics' }),
},
```

- **Key:** an AES-256-GCM key derived from `APP_KEY` with HKDF-SHA256 (purpose `agora:diagnostics:relay`). Every message and job is encrypted and authenticated with it, bound to its channel: **nothing of an event is readable on Redis or in the queue backend**. No crypto server, no key to create, no grant.
- **Where `APP_KEY` comes from:** `config/app.ts`'s `appKey`, else the default entry of `config/encryption.ts` (AdonisJS 7: the first key of `list[default]`, e.g. `drivers.legacy({ keys: [env.get('APP_KEY')] })`), else the `APP_KEY` environment variable. A string or a `Secret`. At least 16 characters. Every Agora lib reads it the same way.
- **Boot:** the transport logs the mode it resolved, once: `[@adonis-agora/diagnostics] redis relay: app key (auto)` (or `queue jobs: app key (auto)`).
- **Rotation:** the relay uses the current `APP_KEY` only; `APP_KEY_LEGACY` (the old keys AdonisJS keeps for decrypting data) is not used, since relay messages live a minute and queue jobs a day at most. Changing `APP_KEY` changes the relay key: during a rolling deploy, processes on the old and new key drop each other's messages until all run the new one, and jobs queued before the switch are refused by workers on the new key.
- **`appKey` in `config/app.ts`:** a string or a `Secret` (`new Secret(env.get('APP_KEY'))`, what AdonisJS apps export) both work; the key is released only to derive the relay key and never logged or shown by `transportInfo` / the doctor.
- **Off:** `crypto: false` turns the automatic mode off (then `secret`, `crypto` or `insecure` is required). Any explicit `secret`, `crypto` or `insecure` is used as given.

**Across apps** (processes of different apps on one relay channel or queue, which don't share an `APP_KEY`): use a shared secret, or an explicit `@adonis-agora/crypto` key, below.

#### Without authkit or crypto: a shared secret

For relays across apps, or when you'd rather not use `APP_KEY`. Crypto is not required: a shared secret is a first-class mode. Generate a long random value once and give the same one to every process that relays (web, workers, other apps on the same `redisChannel` or queue):

```sh title="terminal"
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

```ts title="config/diagnostics.ts"
import env from '#start/env'

redis: transports.redis({ connection: 'main', secret: env.get('DIAGNOSTICS_RELAY_SECRET') }),
queue: transports.queue({ queue: 'diagnostics', secret: env.get('DIAGNOSTICS_RELAY_SECRET') }),
```

```ts title="start/env.ts"
DIAGNOSTICS_RELAY_SECRET: Env.schema.secret(),
```

At least 16 characters. A `Secret` (what `env.get` returns for `Env.schema.secret()`) is accepted as is. Each message carries an HMAC-SHA256; the event itself stays readable on Redis and in the queue. The key is derived from the secret and the channel (the Redis channel; for the queue, the job kind), so the same secret on two channels doesn't let one feed the other, and an event job cannot be passed off as a listener job. To rotate, deploy the new secret to every process; during the rollout, processes on different secrets drop each other's messages.

| | `APP_KEY` (automatic) | Shared secret | Explicit `@adonis-agora/crypto` |
| --- | --- | --- | --- |
| For | the processes of one app | any processes | any processes, across apps |
| Config | none | `secret: env.get('DIAGNOSTICS_RELAY_SECRET')` in every process | `crypto: { cipher }` in every process |
| Messages | encrypted (AES-256-GCM) | HMAC-SHA256; readable on Redis / in the queue | encrypted (AES-256-GCM) |
| Secret to distribute by hand | none (the app's `APP_KEY`) | one, the same in every process | none |
| Who may relay | whoever holds `APP_KEY` | whoever holds the secret | whoever may `encrypt` **and** `decrypt` with the key |
| Rotation and audit | rotate `APP_KEY` | rotate the secret everywhere at once | crypto's (`crypto:keys:rotate`, the crypto audit) |

#### Bring your own

None of `@adonis-agora/authkit`, `@adonis-agora/authz` or `@adonis-agora/crypto` is required: the automatic mode only needs the app's own `APP_KEY`. Everything is a plain option:

- **Your own shared secret**: `secret`, above. Nothing else to install.
- **Your own crypto, KMS or HSM**: `crypto: { cipher, key?, owns? }`, below.
- **No automatic mode**: `crypto: false` turns the `APP_KEY` mode off.

Authorization (authz) does not apply to a relay: there is no viewer and no command, only processes of your deployment that hold the secret or the key.

`crypto: { cipher, key?, owns? }` is never picked by itself, even with `@adonis-agora/crypto` booted. Use it for processes of several apps on one relay (every one of them with a cipher on the same partition and key, `console-diagnostics` by default: create it with `node ace crypto:keys:create console-diagnostics --type aes256-gcm --application <app>` and give every relaying client `crypto:encrypt` **and** `crypto:decrypt` on it), or for a cipher that is not `@adonis-agora/crypto` at all: anything with these two calls works (AWS KMS, Vault transit, an HSM wrapper).

How crypto mode works: each process seals a random session key with the crypto key once an hour, and encrypts its messages with that session key locally; a receiver opens each sender's session key once and caches it. So the crypto server sees about one `encrypt` per process per hour and one `decrypt` per process per sender per hour, not a call per event. Unknown session keys are opened at most 30 times a minute, so junk on Redis cannot flood the crypto server.

```ts title="config/diagnostics.ts"
import crypto from '@adonis-agora/crypto/services/main'

// The app's crypto client, with another key name. A function: config is read before crypto is ready.
redis: transports.redis({ crypto: { cipher: () => crypto.client!, key: 'relay-shared' } }),
```

```ts title="config/diagnostics.ts (your own KMS)"
const kms = {
  encrypt: async ({ key, plaintext, aad }) => ({ ciphertext: await myKms.encrypt(key, plaintext, aad) }),
  decrypt: async ({ key, ciphertext, aad }) => ({ plaintext: await myKms.decrypt(key, ciphertext, aad) }),
}

queue: transports.queue({
  crypto: {
    cipher: kms,
    key: 'diagnostics',
    // The default check expects @adonis-agora/crypto's `agora:ct1:<key>:` ciphertexts.
    owns: (ciphertext) => ciphertext.startsWith('kms:'),
  },
}),
```

The ciphertext must be a single line. Every relaying process needs both `encrypt` and `decrypt` on the key (a `role: 'api'` process only sends; `encrypt` is enough there).

**No authkit token mode.** The federated consoles of the other Agora libs can authenticate with authkit tokens, because there a console sends a command to one app that checks the token and answers. The relays are a broadcast: every process publishes, every process receives, nobody answers. A token would have to be verified by every receiver of every message and each process would need its own authkit client just to say "I am one of us"; `APP_KEY`, a shared secret or a crypto key says exactly that, at no cost per message. So authkit is not used here, even when it is installed.

#### Freshness and replays

On Redis, a message carries its sender, a unique id and a timestamp under the authentication: one over a minute old (or more than a minute ahead: keep clocks in sync) is dropped, and so is an id already seen, so a captured message cannot be replayed.

A queue job waits in a backlog and is retried with the same payload, so it gets its own rules: a job is valid for `maxJobAgeMs` after it was dispatched (default 24 hours; set it on `transports.queue({ maxJobAgeMs })`), and its message is bound to the queue's **job id** the first time a worker opens it. The same job retried (same job id, any attempt) passes; the same message in another job (a copy written into the backend) is refused as a replay. The ids are remembered for the age window in each worker process.

A dropped message or refused job is logged as a warning, once per reason per process (`AGORA_DIAGNOSTICS_RELAY_REJECTED` for Redis, `AGORA_DIAGNOSTICS_QUEUE_JOB_REJECTED` for jobs), never thrown. A refused listener job completes without running the listener and is not retried: retrying would not change the verdict.

#### When nothing resolves: the boot error

Without an `APP_KEY` and nothing configured (or with `crypto: false` and nothing else), the transport throws at boot, naming the options in order:

```
[@adonis-agora/diagnostics] the queue transport needs authentication. Set APP_KEY in this app (automatic for the processes of one app: nothing else to configure; `node ace generate:key`), or set `secret` (...), or `crypto: { cipher }` (@adonis-agora/crypto or your own KMS, for relays across apps). For local development only, `insecure: true` relays without authentication.
```

The check runs where the transport starts (the provider's `ready`, so a web server, a `queue:work` worker, any command that starts the app); ace commands that don't start the app are unaffected. `node ace agora:doctor` reports the resolved mode without booting (`diagnostics.relay-auth`: `app key (auto)`, `secret`, `crypto (key …)`, or the error). With an explicit `crypto`, its deep check `diagnostics.relay-auth-key` (`--deep`, with the app booted) probes the key: this process encrypts and decrypts with it. The `APP_KEY` mode has no key to probe.

#### Local development: `insecure: true`

`transports.redis({ insecure: true })` / `transports.queue({ insecure: true })` relay without authentication, the way earlier versions did, and warn at boot (`AGORA_DIAGNOSTICS_INSECURE_RELAY`). Use it only on a Redis or queue backend nothing else can reach; `node ace agora:doctor` flags it.

### What a received event may create

Every new `(lib, event)` pair a process sees becomes a channel it keeps for its lifetime, with subscriptions from the recent-events buffer, the relay and the OTel bridge. So even an authenticated relay only re-emits an event whose `lib` matches `[A-Za-z0-9][A-Za-z0-9_-]{0,63}` and whose `event` matches `[A-Za-z0-9][A-Za-z0-9_.:-]{0,127}`, on a channel this process already knows or one of at most `maxRemoteChannels` (default 256) new ones. Past that, events on channels this process has never seen are dropped with a warning; events on known channels keep flowing. The queue relay applies the same names and cap (`createDiagnosticsQueueRelay({ maxRemoteChannels })`). A relayed copy is never forwarded again, by any relay in the process.

## The queue transport

`transports.queue(config)` relays over [`@adonisjs/queue`](https://github.com/adonisjs/queue). A forwarded event is dispatched as the `agora.diagnostics.event` job, carrying a `DiagnosticsEventEnvelope`; a **worker running in another process** executes that job and re-emits the event onto its local bus.

```ts
transports.queue({
  queue: 'diagnostics', // queue to dispatch onto — omit for the job's default queue
  // nothing to add: the app's APP_KEY authenticates it (across apps: secret or crypto)
  maxJobAgeMs: 24 * 60 * 60_000, // how long a job stays valid (backlog and retries); the default
})
```

The envelope on the wire is deliberately small:

```ts
interface DiagnosticsEventEnvelope {
  node: string          // id of the process that forwarded the event
  env: DiagnosticEvent  // the original envelope, exactly as emitted
}
```

`node` is what makes echo suppression work: a process ignores any envelope stamped with its own id. `env` is untouched — `ts`, `lib`, `event`, `traceId`, `payload` and `durationMs` arrive on the far side exactly as `emit` built them, so a remote `onDiagnostic` handler cannot tell the event came over the wire.

That envelope is what the relay seals: on the queue it travels as `{ sealed }`, a message authenticated like a Redis relay message (encrypted with the `APP_KEY` mode and in crypto mode), and the worker re-emits it only once it opened. A job without a valid seal is refused. See [Authenticating the relays](#authenticating-the-relays). A worker still re-emits only valid `lib`/`event` names on a bounded number of new channels (see [What a received event may create](#what-a-received-event-may-create)).

A worker must be running to receive forwarded events. `queue` is a **flag** on `queue:work`, not a positional argument — pass a bare name and the worker silently starts on the `default` queue instead, where the relay never dispatches anything:

```sh title="terminal"
node ace queue:work --queue=diagnostics
```

A process that starts this transport can run the worker for it as-is: the job is resolvable there by its name, `agora.diagnostics.event`, whether or not your `locations` glob covers the package. Forwarding is fire-and-forget: a queue outage is reported, never thrown into `emit()`. The events of one turn are pushed with a single `DiagnosticsEventJob.dispatchMany(...)` (on the configured `queue`), which still creates one job per event; a turn with a single event uses `dispatch`.

### Listeners on the queue

With `queue` selected, [listeners](/docs/diagnostics/listeners) don't run in the process that emits the event. That process dispatches one `agora.diagnostics.listener` job per `(listener, event)` onto the same `queue`, and a worker runs the listener. When the handler throws, the job fails and `@adonisjs/queue` retries it:

```ts
transports.queue({
  queue: 'diagnostics',
  retries: 5, // retries after a failed attempt (default 3)
})
```

Listener jobs are sealed the same way (`{ sealed }` carrying the listener id and the event), so nobody who can write into the queue backend can run a listener with input of their choosing. Delivery is at-least-once, so make listeners idempotent on `event.id`. The worker must run the same app and config, so it has the same listeners; start it on the transport's queue:

```sh title="terminal"
node ace queue:work --queue=diagnostics
```

### When dispatching fails

`job.dispatch(...)` and `job.dispatchMany(...)` reach a network backend, so they can reject. The relay never lets that reach the `emit()` that triggered it — the rejection is routed to `onDispatchError` instead, once per failed call, so a failed `dispatchMany` is reported once for its whole batch. A hook that throws is contained too. Through `transports.queue(...)` it is already wired to the application logger:

```
[error] failed to relay diagnostics event to queue
```

Wiring your own is a one-liner when you drive the relay directly, and it is the only way to notice that fan-out has silently stopped:

```ts
import { createDiagnosticsQueueRelay } from '@adonis-agora/diagnostics'

const stop = createDiagnosticsQueueRelay({
  job: DiagnosticsEventJob,
  all: true,
  secret: env.get('DIAGNOSTICS_RELAY_SECRET'), // or crypto: { cipher }
  onDispatchError: (error) => {
    metrics.increment('diagnostics.relay.dispatch_failed')
    logger.error({ err: error }, 'diagnostics relay could not reach the queue')
  },
})
```

Omit it and dispatch failures are swallowed: events simply stop arriving on the other side, with nothing in the logs to say why.

### Worker-only processes

This is the number-one reason forwarded events don't arrive. Re-emission happens through a **re-emitter bound in the worker's own process**, and starting the transport is what binds one. A worker process that never starts the transport runs the job as a **no-op**: it succeeds, the queue reports it processed, and no local handler ever fires.

So the worker needs the transport selected too — it is not enough for the web process to have it. To keep the web process from consuming at the same time, set [`role`](#split-deployments) per process. What the worker does *not* need is to forward anything of its own; an empty `forward` gives you a pure consumer:

```ts title="config/diagnostics.ts"
import env from '#start/env'
import { defineConfig, transports } from '@adonis-agora/diagnostics'

export default defineConfig({
  default: 'queue',

  // The web process fans out; the worker only consumes.
  forward: env.get('DIAGNOSTICS_FORWARD', false) ? { all: true } : {},

  transports: {
    queue: transports.queue({ queue: 'diagnostics' }),
  },
})
```

The trap is gating `default` itself on the environment: with `default` unset the worker starts no transport, binds no re-emitter, and every relayed event is silently dropped there. Gate `forward`, not `default`.

`getActiveReEmitter()` is how you check, in the process itself, which side of that line you're on. It returns `null` when nothing is bound — the exact state in which relayed events go nowhere:

```ts
import { getActiveReEmitter } from '@adonis-agora/diagnostics'

if (getActiveReEmitter() === null) {
  logger.warn('diagnostics: no re-emitter bound — relayed events are dropped in this process')
}
```

`bindRelayReEmitter` is the matching low-level seam, for wiring a re-emitter without starting a relay — a non-Adonis worker, or a test that exercises the job directly:

```ts
import { bindRelayReEmitter } from '@adonis-agora/diagnostics'

const unbind = bindRelayReEmitter({
  nodeId: 'reporting-worker',
  // Binding always installs the package's own re-emit, keyed on the nodeId above,
  // so the loop guard can never be bypassed — this member is not called.
  reEmit: () => {},
})

// …on shutdown
unbind()
```

What you really bind is the `nodeId`: envelopes stamped with it are dropped as this process's own echo, and every other envelope is published onto the local bus under its original `lib`/`event`, so `onDiagnostic('billing', …)` here fires for an event emitted in the web process. Binding is last-write-wins — a later call replaces the current re-emitter, and the returned unbind clears it only if it is still the active one.

The job also needs the job authentication to open its payload, which starting the transport binds (`bindQueueJobAuth(createQueueJobAuth({ secret }))` does it by hand). With a re-emitter but no job authentication, the job is a no-op.

<Callout type="warn" title="A queue is fan-out, not request/response">
The relay only dispatches; it never waits. That fits diagnostics (you want events to spread, not to block the emitter). Pick the queue transport when a queue is already your cross-process backbone; pick Redis when you want a dedicated low-latency pub/sub path.
</Callout>

## The durable transport

`transports.durable(options)` runs each [listener](/docs/diagnostics/listeners) as a durable run of [`@adonis-agora/durable`](/docs/durable): one run per `(listener, event)`, started from the process that emitted the event and executed by any durable worker. A failing listener is retried with backoff, every attempt is visible in the durable console, and the same event never starts the same listener twice.

```ts title="config/diagnostics.ts"
import { defineConfig, transports } from '@adonis-agora/diagnostics'

export default defineConfig({
  default: 'durable',
  transports: {
    durable: transports.durable({
      retries: 5,        // attempts before the run fails
      backoff: 'exp',    // 'fixed' or 'exp'
      backoffMs: 1000,   // base delay between attempts
      backoffMaxMs: 60_000,
      jitter: true,
    }),
  },
})
```

Every option is optional. `@adonis-agora/durable` must be installed and configured in the app. When `durable` is the selected `default` and it isn't, the app fails at boot, not on the first event:

| Situation | Error at boot |
| --- | --- |
| `@adonis-agora/durable` is not installed | `` `transports.durable()` requires @adonis-agora/durable. Install it and run `node ace configure @adonis-agora/durable`, or pick another transport. `` |
| it is installed but too old to provide `@adonis-agora/durable/diagnostics` | `` `transports.durable()` requires a version of @adonis-agora/durable that exports `@adonis-agora/durable/diagnostics`. Upgrade @adonis-agora/durable, or pick another transport. `` |
| it is installed but not configured | `` `transports.durable()` requires @adonis-agora/durable to be configured: no durable engine is bound in the container. Run `node ace configure @adonis-agora/durable` and register its provider, or pick another transport. `` |

Listing `durable` without selecting it costs nothing, so a config can name it in every environment and select it only where durable runs.

## Split deployments

When the web and worker processes of an app are deployed separately, set `role` per process, from the environment, so the same config file serves both:

```ts title="config/diagnostics.ts"
import env from '#start/env'
import { defineConfig, transports } from '@adonis-agora/diagnostics'

export default defineConfig({
  default: 'queue',
  role: env.get('DIAGNOSTICS_ROLE', 'all'),
  forward: { libs: ['resilience'] },
  transports: {
    queue: transports.queue({ queue: 'diagnostics' }),
  },
})
```

```ts title="start/env.ts"
DIAGNOSTICS_ROLE: Env.schema.enum.optional(['all', 'api', 'worker'] as const),
```

| `role` | What this process does |
| --- | --- |
| `'all'` (default) | Everything: emits, forwards, receives what other processes forward, runs listeners. |
| `'api'` | Emits, forwards through the `default` transport and hands listener work to it. Never receives events from other processes and never runs a listener. |
| `'worker'` | Receives and runs listeners. Diagnostics mounts no route, so a worker does everything `'all'` does. |

### What each role does per transport

| transport | `'api'` | `'worker'` / `'all'` | runs the worker half |
| --- | --- | --- | --- |
| `redis` | Publishes the `forward` channels and the libs your listeners listen to. Opens no subscriber connection, so events from other processes never reach it. | Subscribes, re-emits what other processes publish, and runs listeners for every event it sees, its own included. | Any long-running process booted with that role: no extra command. |
| `queue` | Dispatches `agora.diagnostics.event` jobs and one `agora.diagnostics.listener` job per `(listener, event)`. A relay job run here re-emits nothing, and a listener job fails so the queue retries it elsewhere. | Runs both jobs: re-emits relayed events and runs listeners, with retries. | `node ace queue:work --queue=diagnostics` |
| `durable` | Starts one durable run per `(listener, event)`. | Executes those runs. | `node ace durable:work` |

With `redis`, every `'worker'` and `'all'` process runs each listener, so three worker replicas run it three times. Use `queue` or `durable` when a listener must run once.

With `durable`, durable decides which process executes a run. A durable engine executes the runs it starts in-process by default, so on the api pods set `drive: false` in `config/durable.ts` (and `consumers: 'never'` when the transport has a broker) to leave every run to `durable:work`.

`onDiagnostic(lib, event, fn)` functions and raw channel subscribers (Telescope, OpenTelemetry) are not listeners: on an `'api'` process they still fire, for the events that process emits.

<Callout type="warn" title="A split needs a transport">
Without a `default` transport each process only sees its own events: an `'api'` process would drop its listeners' work and a `'worker'` would never receive anything. Boot fails instead:

```text
@adonis-agora/diagnostics: config.role is "api", which splits emitting from consuming — but no `default` transport is selected, so nothing carries events between the two halves. Select a transport with `default`, or drop `role`.
```
</Callout>

## Write your own transport

`transports.redis` and `transports.queue` are not privileged — `config.transports` is a plain `Record<string, TransportProvider>`, and a `TransportProvider` is any thunk with this shape:

```ts
type TransportProvider = (ctx: TransportContext) => Promise<(() => void) | TransportHandle>

interface TransportContext {
  app: ApplicationService      // the booted app — resolve the logger, connections, config…
  forward: ChannelSelection    // the config's `forward`, ready to hand to createChannelSelector
  nodeId?: string              // this process's id
  listeners?: ChannelSelection // the libs your listeners listen to
  invoke?: ListenerInvoker     // runs a registered listener in this process
  listenerIds?: readonly string[]
}

interface TransportHandle {
  stop?(): void | Promise<void>
  deliver?(deliveries: readonly ListenerDelivery[]): void | Promise<void>
}
```

The thunk is called once, after the container is ready, and only for the transport named by `default`. A relay returns a **synchronous** teardown, which runs on graceful shutdown — kick off async closes from inside it, but don't return a promise. Everything the transport opened is its own to close there: a socket left open keeps the process from exiting.

To be a good citizen a transport does four things: subscribe with `createChannelSelector`, stamp each outgoing event with `nodeId`, drop incoming events stamped with its own `nodeId`, and guard a re-emitted event from being forwarded straight back out. Here is a complete NATS transport doing all four:

```ts title="config/diagnostics.ts"
import { randomUUID } from 'node:crypto'
import { connect } from 'nats'
import { createChannelSelector, defineConfig, getChannel } from '@adonis-agora/diagnostics'
import type { DiagnosticEvent, TransportProvider } from '@adonis-agora/diagnostics'

const SUBJECT = 'agora.diagnostics.relay'

function natsTransport(servers: string): TransportProvider {
  return async (ctx) => {
    const nc = await connect({ servers })
    const logger = await ctx.app.container.make('logger')
    const nodeId = ctx.nodeId ?? randomUUID()
    const encoder = new TextEncoder()
    const decoder = new TextDecoder()

    // Events we just re-emitted from the network — never send them back out.
    const reEmitting = new WeakSet<object>()

    const forward = (msg: unknown) => {
      if (typeof msg !== 'object' || msg === null) return
      if (reEmitting.has(msg)) return
      try {
        nc.publish(SUBJECT, encoder.encode(JSON.stringify({ node: nodeId, env: msg })))
      } catch (err) {
        // forward() runs inside emit() — it must never throw back into the caller
        logger.error({ err }, 'diagnostics: NATS publish failed')
      }
    }

    const selector = createChannelSelector(ctx.forward, forward)

    const subscription = nc.subscribe(SUBJECT)
    void (async () => {
      for await (const message of subscription) {
        let parsed: { node?: unknown; env?: DiagnosticEvent }
        try {
          parsed = JSON.parse(decoder.decode(message.data))
        } catch {
          continue // ignore malformed
        }
        if (parsed.node === nodeId) continue // our own echo
        const env = parsed.env
        if (!env || typeof env.lib !== 'string' || typeof env.event !== 'string') continue

        reEmitting.add(env)
        try {
          getChannel(env.lib, env.event).publish(env)
        } catch {
          // a local subscriber threw — never propagate it into the network loop
        } finally {
          reEmitting.delete(env)
        }
      }
    })()

    // Synchronous teardown: stop forwarding, then close what we opened.
    return () => {
      selector.stop()
      subscription.unsubscribe()
      void nc.drain()
    }
  }
}

export default defineConfig({
  default: 'nats',
  forward: { all: true },
  transports: {
    nats: natsTransport('nats://127.0.0.1:4222'),
  },
})
```

`createChannelSelector(selection, forward)` is the same engine both built-in transports use. It subscribes `forward` to every channel matched by the selection — the exact `channels`, every channel of the wildcard `libs`, or all of them — including channels registered **after** the relay started, so a lib whose first event fires an hour into the process is picked up automatically. Each channel is subscribed at most once, and `selector.stop()` removes every subscription plus the future-registration listener.

### A transport that runs listeners

Return a handle with `deliver` to take over listener execution, as `queue` and `durable` do. The emitting process calls `deliver` with each `(listener, event)` pair once, after `emit()` returned; wherever you run the work, call `ctx.invoke(listenerId, envelope)`, which rejects with the listener's error so you can retry. `envelope.id` is the event id: `diag:${envelope.id}:${listenerId}` is a good idempotency key.

```ts title="config/diagnostics.ts"
import { defineConfig } from '@adonis-agora/diagnostics'
import type { TransportProvider } from '@adonis-agora/diagnostics'
import Outbox from '#models/outbox'

function outboxTransport(): TransportProvider {
  return async (ctx) => ({
    async deliver(deliveries) {
      await Outbox.createMany(
        deliveries.map(({ listenerId, envelope }) => ({
          key: `diag:${envelope.id}:${listenerId}`,
          listenerId,
          envelope: JSON.stringify(envelope),
        })),
      )
    },
    // An outbox poller elsewhere calls ctx.invoke(row.listenerId, JSON.parse(row.envelope))
  })
}

export default defineConfig({
  default: 'outbox',
  transports: { outbox: outboxTransport() },
})
```

The types are importable without loading diagnostics at runtime, from `@adonis-agora/diagnostics/delivery` (`ListenerDeliveryTransport`, `ListenerDelivery`, `DeliveryTransportContext`, `ListenerInvoker`).

<Callout type="warn" title="Never throw out of forward()">
`forward` runs **inline** inside the `emit()` that produced the event. A throw there would surface in unrelated application code, and a slow call there slows down the emitting request. Catch everything, and keep the send non-blocking. The built-in transports [only queue there](#forwarding-cost-on-the-emitter) and send once per turn.
</Callout>

## Advanced: the relays without AdonisJS

The transport factories wrap two framework-agnostic functions, exported for non-Adonis use, tests, or custom wiring. They take the raw collaborators (a Redis client pair, or a job with `dispatch`) and the same selection options. Both return a teardown that sends any queued events, then removes every local subscription:

```ts
import { createDiagnosticsRedisRelay, createDiagnosticsQueueRelay } from '@adonis-agora/diagnostics'

const stop = createDiagnosticsRedisRelay({
  pub,
  sub,
  libs: ['resilience'],
  nodeId: 'A',
  secret: process.env.DIAGNOSTICS_RELAY_SECRET, // or crypto: { cipher }, or insecure: true
})
// (Outside AdonisJS there is no automatic mode: pass `appKey`, `secret`, `crypto` or `insecure`.)
// …later
stop()
```

### `DiagnosticsRedisRelayOptions`

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `pub` | `RedisLike` | — | Publisher connection. Required. |
| `sub` | `RedisLike` | — | Subscriber connection, **separate** from `pub` (a subscribed client can't publish). For ioredis: `const sub = pub.duplicate()`. Required unless `receive` is `false`. |
| `receive` | `boolean` | `true` | `false` publishes only: no `sub`, no events from other processes. What `transports.redis` does on a `role: 'api'` process. |
| `libs` | `string[]` | — | Forward every event of these libs, current and future channels. |
| `channels` | `ChannelRef[]` | — | Forward these exact `{ lib, event }` pairs, in addition to `libs`. |
| `all` | `boolean` | `false` | Forward every `agora:` channel. Overrides `libs`/`channels`. |
| `redisChannel` | `string` | `agora:diagnostics:relay` | The Redis channel to relay on. Every process that should see each other's events must agree on it. |
| `nodeId` | `string` | random | Id stamped on outgoing messages; incoming messages carrying it are dropped as this process's own echo. |
| `secret` | `string \| { release(): string }` | — | Shared secret (16+ characters) every relaying process holds. One of `appKey`, `secret`, `crypto`, `insecure` is required here (the automatic `APP_KEY` mode is a `transports.redis()` feature). See [Authenticating the relays](#authenticating-the-relays). |
| `appKey` | `string \| { release(): string }` | — | The app's `APP_KEY` (16+ characters): what the AdonisJS transports use automatically. |
| `crypto` | `{ cipher: RelayCipher \| () => RelayCipher, key?: string, owns?: (ciphertext) => boolean }` | — | Authenticate and encrypt with an `@adonis-agora/crypto` key (default `console-diagnostics`), or your own KMS. |
| `insecure` | `boolean` | `false` | Relay without authentication. Local development only; warns. |
| `maxRemoteChannels` | `number` | `256` | How many channels received events may create beyond those this process registered. |
| `onError` | `(error: Error) => void` | process warning | Called once per reason when a received message is dropped (`error.reason`: `unauthenticated`, `stale`, `replayed`, `malformed`, `invalid-channel`, `channel-cap`, `overloaded`) or the crypto cipher fails (`crypto-unavailable`). `transports.redis` logs it as a warning. |

Neither connection is closed by `stop()` — the relay only flushes, unsubscribes and detaches its message listener, because it opened neither. Closing is the caller's job, which is exactly what the `transports.redis` factory does for the `duplicate()` it created.

`pub`/`sub` are typed structurally, so you are not tied to ioredis. Anything with these five methods works, including a fake in a test. `pipeline()` is optional: ioredis has it, and with it a turn's events go out as one pipeline. A client without it gets one `publish` per event in the same drain.

```ts
interface RedisLike {
  publish(channel: string, message: string): unknown
  pipeline?(): { publish(channel: string, message: string): unknown; exec(): unknown }
  subscribe(channel: string, callback?: (err: Error | null, count: number) => void): unknown
  on(event: 'message', listener: (channel: string, message: string) => void): unknown
  removeListener(event: 'message', listener: (channel: string, message: string) => void): unknown
  unsubscribe(channel: string): unknown
}
```

### `DiagnosticsQueueRelayOptions`

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `job` | `DiagnosticsEventJobLike` | — | The job used to forward events. Each turn's events go to `dispatchMany(envelopes)` when the job has it, else to `dispatch(envelope)` one by one. Required. |
| `libs` | `string[]` | — | Forward every event of these libs, current and future channels. |
| `channels` | `ChannelRef[]` | — | Forward these exact `{ lib, event }` pairs, in addition to `libs`. |
| `all` | `boolean` | `false` | Forward every `agora:` channel. Overrides `libs`/`channels`. |
| `nodeId` | `string` | random | Id stamped onto every dispatched envelope; envelopes carrying it are dropped as this process's own echo. |
| `receive` | `boolean` | `true` | `false` forwards only and binds no re-emitter. What `transports.queue` does on a `role: 'api'` process. |
| `maxRemoteChannels` | `number` | `256` | How many channels received events may create beyond those this process registered. Events with an invalid `lib`/`event` name are dropped. |
| `appKey` / `secret` / `crypto` / `insecure` | as for the Redis relay | — | How jobs are sealed and opened. One is required. |
| `maxJobAgeMs` | `number` | 24 hours | How long a dispatched job stays valid (backlog and retries included). |
| `onError` | `(error: Error) => void` | process warning | Called once per reason when a job a worker runs here is refused (`error.reason`: `unsealed`, `unauthenticated`, `stale`, `replayed`, `malformed`) or the crypto cipher fails. |
| `onDispatchError` | `(error: unknown) => void` | ignored | Called when `dispatch` or `dispatchMany` throws or rejects, once per failed call. See [When dispatching fails](#when-dispatching-fails). |

`job` is structural too — anything whose `dispatch(payload)` returns a promise (or nothing) satisfies it, which is what makes the relay testable without a queue backend. `dispatchMany` is optional; the `@adonisjs/queue` job class has it. Without it, every event in a turn gets its own `dispatch`:

```ts
interface DiagnosticsEventJobLike {
  dispatch(payload: DiagnosticsEventEnvelope): PromiseLike<unknown> | unknown
  dispatchMany?(payloads: DiagnosticsEventEnvelope[]): PromiseLike<unknown> | unknown
}

const dispatched: DiagnosticsEventEnvelope[] = []
const stop = createDiagnosticsQueueRelay({
  job: { dispatch: (payload) => dispatched.push(payload) },
  all: true,
  nodeId: 'test-node',
})

emit('billing', 'invoice-paid', { invoiceId: 'inv_123' })

stop() // sends the queued event before unsubscribing
expect(dispatched[0].node).toBe('test-node')
expect(dispatched[0].env.event).toBe('invoice-paid')
```

Starting the relay also binds the process re-emitter, and `stop()` unbinds it — which is why a process running a relay receives relayed events with no extra wiring, and a process that never starts one [drops them](#worker-only-processes).
